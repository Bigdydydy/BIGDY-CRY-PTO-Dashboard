# 项目复盘：踩过的坑与可复用的做法

> 范围：2026-09-12 首次提交 → 2026-11-17，约 630 个提交（不含机器人快照），外加两份质检/审计报告（[qa-2026-10-29](reports/qa-2026-10-29.md)、[audit-2026-11-11](reports/audit-2026-11-11.md)）。
> 目的：以后做类似项目（数据看板 / 爬取 + 定时任务 + 免费托管）或其他项目时，开工前扫一遍，少走回头路。
> 每条格式：**现象 → 根因 → 做法**。带 ★ 的是代价最大、最值得提前防的。

项目形态回顾：Node 单进程服务（无框架）+ 纯前端静态页，部署在 **Render 免费实例（新加坡）**；**GitHub Actions 当定时器兼存储**（采集脚本把 JSON 提交回仓库）；数据来自十几个外部源，其中有交易所公开 API，也有逆向的私有接口。

## 1. 托管：Render 免费实例

| | 现象 | 根因 | 做法 |
|---|---|---|---|
| ★1.1 | 部署超时失败 | 启动时先拉数据再 `listen`，超过 Render 端口探测时限 | **先绑定端口、先暴露 `/healthz`**，数据在后台预热 |
| 1.2 | 首次访问要等 30–60 秒；"30 秒后台刷新"在没人访问时根本不跑 | 15 分钟无流量即休眠 | 页面与 README 明说"实时只在有人访问时成立"；需要持续采集的东西交给 Actions，不要指望 Web 进程常驻 |
| 1.3 | 服务器本地累积的数据（`*.local.json`、波动率档案、定稿 K 线）重启后清零 | 免费实例文件系统不持久 | 凡是要长期保存的序列，都由 CI 生产并提交；服务器只"读归档 + 叠加实时点" |
| 1.4 | 一次波浪分析把整个服务卡住 10+ 秒 | 0.1 CPU + 单事件循环，10000 根 K 线分析约 1.2 s 本地 CPU | 重计算挪到**浏览器 Web Worker**，服务器只供缓存好的原始数据（`24792be`） |
| ★1.5 | 限流按 IP 生效失败，所有访客共用一个额度 | `X-Forwarded-For` 实际是 `[访客, Cloudflare 边缘, Render 内网代理]` 三段，`TRUST_PROXY_HOPS=1` 取到的是内网代理 | 别猜代理层数：**上线后打一条临时日志看真实头的形态**再定值（最终为 3，见 `4c0aa32`） |
| 1.6 | `render.yaml` 里的环境变量 / 构建命令可能没生效 | 只有按 Blueprint 创建的服务才读 `render.yaml`，控制台手建的服务不读 | 部署侧配置要在控制台核对一次，不要只看仓库 |

## 2. 外部数据源：地域封锁、限流与"私有接口负债"

| | 现象 | 根因 | 做法 |
|---|---|---|---|
| ★2.1 | 本地正常，线上 Binance 返回 **418 / 451**，模块冻结在旧缓存上数天没人发现 | 云主机共享出口 IP 被 Binance 封；镜像域名 `data-api.binance.vision` 同样被拒 | **任何单一来源都要有备用源**：K 线 Binance→Bybit→OKX；现货日线 Binance→OKX→Coinbase（[spot_daily.js](../server/spot_daily.js)）；期限结构整体改用 Deribit。备用源要在数据上**标注来源**，且同一次计算的各条腿必须来自同一交易所，不能混 |
| 2.2 | 反过来：线上能访问的源，本地访问不了 | 大陆网络屏蔽 Binance；本地网络对 Coinbase 全部域名做了自签名证书拦截 | 本地服务器可以"回退到线上站点的 API"（[upstream_mirror.js](../server/upstream_mirror.js)），但必须：默认关闭、禁止指向自身、不落盘、健康状态如实标为"经线上转发" |
| ★2.3 | Deribit 返回 **429**，历史序列停更 | 每次刷新从 2024-01 全量重建，约 50 个请求同时发出 | **增量刷新**（只重算最近 10 天）+ 单一请求队列（≥250 ms 间隔）+ 429 退避重试 1s/3s/8s（`905bb1e`） |
| 2.4 | strategy.com 自某天起对非浏览器客户端返回 Akamai 403 | 反爬升级 | 找官方的第二条路径（SEC 8-K 解析），并把"走了哪条路径"写进健康状态 |
| 2.5 | DefiLlama 1.3 MB 的响应偶尔超过 12 s，整个模块变 STALE | 超时按"平均情况"设置 | 超时**按源**设置；大响应给足时间；失败时在 last-good 历史上继续计算，不要整模块掉线 |
| ★2.6 | 期权板块（Greeks.live）、CDRI（CoinGlass）都靠逆向私有接口：写死的 RSA 公钥签名、AES-ECB 解密 | — | 把私有接口当**负债**记账：能用公开 API 自算的（Deribit 现货、ATM IV、Smile、Skew、GEX、大宗）优先自算，私有接口降级为交叉核对。仓库若是公开的，密钥和逆向细节对方很容易发现 |
| 2.7 | 抓取的课程全文放进了公开仓库 | — | 第三方内容不进公开仓库（版权风险）；只留自己的笔记与引用 |

**通用 HTTP 约定**（最后沉淀在 [http_client.js](../server/http_client.js)）：默认 10 s 超时 / 重试 1 次；单飞锁合并并发请求；失败冷却（例如失败后 15 分钟内不再重建）；失败**不覆盖** last-good；原子写盘；缓存过期时"先回旧数据、后台刷新"（[swr.js](../server/swr.js)，最多等上游 1.2 s）。

## 3. GitHub Actions 当定时器 + 存储

| | 现象 | 根因 | 做法 |
|---|---|---|---|
| ★3.1 | 每小时的任务**一次都没跑过**；每日任务晚 2–3.5 小时甚至整段丢弃 | GitHub 定时任务在高峰期（尤其整点、00:00 UTC 附近）延迟或丢弃，这是常态 | **一个周期排多个时段**（如每小时 `7,23,38,52`），配合 `--skip-if-filled` / `--skip-if-final` 让第一个成功的落地、后续直接退出；避开整点；可用外部定时器调 `workflow_dispatch` 兜底 |
| 3.2 | 连续两次运行标成同一天或跳过一天 | 用"运行时刻"给数据贴日期，而运行时刻漂移了几小时 | 日期标签用 **（运行时刻 − 12h）** 这类与漂移无关的规则，或直接用数据本身的日期 |
| 3.3 | 后一个时段看不到前一个时段的提交，`--skip-if-filled` 失效、push 冲突 | `actions/checkout` 默认检出触发时的 SHA | `checkout` 加 `ref: main`；push 前 `git pull --rebase` 并重试 3 次；`concurrency` 组防并发 |
| 3.4 | 每次机器人提交都触发一次 Render 重新部署；后续时段只改了 `generated_at` 也产生提交 | — | 提交信息带 `[skip ci] [skip render]`；**已定稿的数据直接退出、不碰文件**（`7f87986`）；`git diff --cached --quiet` 时不提交 |
| 3.5 | 采集失败但任务显示绿色 | 脚本吞掉异常 | 保存成功的部分，但**有任何失败就非零退出**，让任务变红 |
| 3.6 | `.git` 涨到 25 MB，一个月 900+ 提交里约 770 个是机器人快照 | 数据和代码在同一分支 | 新项目：数据归档放**独立 orphan 分支或对象存储**，main 只放代码；或把小时快照攒成每日一次提交 |
| 3.7 | 健康巡检 55/55 次失败 | 15 s 超时去打一个休眠中的免费实例（冷启动 30–60 s） | 巡检先请求 `/healthz` 唤醒，再给 90 s 预算 |

## 4. 数据持久化与"唯一真相源"

| | 现象 | 根因 | 做法 |
|---|---|---|---|
| ★4.1 | 本地每启动一次服务，`git status` 就多出一堆改动的 `data/*.json`；CI 提交、服务器写入、本地写入三方互相覆盖 | 运行时改写受 git 跟踪的文件 | 一开始就定规矩：**CI 是唯一的归档生产者**；服务器的运行时产物一律写 `*.local.json` 并 gitignore |
| 4.2 | 上一条修完后，`.local.json` 只在首次启动时从正式归档复制一份，此后永远遮住 `git pull` 带来的新数据 | 种子文件只播种一次 | 加载时与正式归档**按主键合并**，或"正式文件更新时重新播种" |
| 4.3 | 缓存新鲜度判断在重新部署后全错 | 用文件 mtime 判断，而 git checkout / 部署会重置 mtime | 新鲜度看**载荷里自带的时间戳**（数据日期），不看 mtime |
| ★4.4 | 归档 JSON 解析失败 → 当作空数组 → 与新数据合并 → 写回，60 天历史被静默清空 | "读失败返回空"是危险的默认值 | 读取失败要**抛错并拒绝写盘**，或先把原文件改名留底 |
| 4.5 | 一个归档写盘失败，整轮刷新被丢弃 | 非关键 IO 和主流程在同一个 try 里 | 关键路径与附属写入分开处理 |

## 5. 数据健康监测：防漏报，也要防误报

最终方案见 [data_resilience.md](data_resilience.md)。几条关键教训：

- **区分两个时钟**：`lastSuccessAt`（真实成功回执的时刻）与 `dataAsOf`（数据内容自身的日期）。失败只推进 `lastAttemptAt`，不推进这两个。不能拿"下载时间"当数据日期伪装新鲜。
- **从未核验 = UNKNOWN**，不是 OK。冷启动的模块从 UNKNOWN 开始。
- ★**误报和漏报一样有害**：
  - 日度归档每天只产生一行，却套用 2 小时的回执窗口 → 每天约 22 小时黄灯（`5d66263`，改为 26h）。
  - ETF OI "任何 null 即整源失败"，而 CME 周末本来就休市 → 整个模块停更两周。
  - 线上因 Binance 封锁而长期 DEGRADED（已用标注好的备用源）→ 巡检每小时变红，真正的 CRITICAL 被淹没。改为只有 CRITICAL / UNKNOWN 让任务失败（`baa0fcd`）。
- 阈值要**按每个源的实际更新节奏**单独设，而不是一套窗口套全部。
- 健康系统本身也应有"误报率"指标（每个源过去 7 天处于非 OK 的时长），超标的源回头校准策略。

## 6. 安全与健壮性（公开站点的底线）

审计时一次性发现的问题，新项目开工就该做掉：

| | 问题 | 做法 |
|---|---|---|
| ★6.1 | 三种畸形请求（重复查询参数变数组、请求体 `null`、`{"symbol":1}`）直接让 Node 进程退出 | 外层 handler 包 `try/catch` 统一返回 500；注册 `process.on('unhandledRejection')`；查询参数一律 `String(...)`；请求体不是普通对象就 400 |
| 6.2 | 11 个 GET 接口接受 `?force=1` 绕过缓存，无鉴权无限流 → 任何人都能让出口 IP 被上游封 | 强制刷新只对本机或带密钥的请求生效；全局冷却只由真正的刷新路径消耗（预检 `OPTIONS`、404 不能占用冷却） |
| 6.3 | 限流读 `X-Forwarded-For` 第一个值（客户端可伪造）；限流表无上限增长 | 按已知代理层数**从右往左**取；限流表设硬上限 |
| 6.4 | 自由整数参数（如 `threshold`）每个新值都触发一次完整重算 | 参数收敛到固定档位；缓存键有界 |
| 6.5 | 所有响应带 `Access-Control-Allow-Origin: *`，包括 POST | 写操作不开通配 CORS |
| 6.6 | 静态文件服务 | 加路径穿越防护 |

## 7. 性能

- 静态资源原先 `no-store` 且不压缩，每次访问重新下载 2 MB → 内存中预压缩 gzip + ETag + `no-cache`：首访约 0.6 MB，复访 304（`24792be`）。
- `/api/market-data` 每次返回约 1.8 MB，内含与其他接口重复的大序列 → 拆掉重复字段；整份响应按输入签名缓存，重复请求从 1.5–4.7 s 降到约 0.2 s（`08a4b09`）。
- 大模块（图表库 + 波浪引擎约 440 KB）**懒加载**，首次打开该视图再加载。
- 后台轮询在 5 分钟无访问后暂停；按视图决定轮询频率（看不到的数据不刷）。
- Google Fonts 的渲染阻塞 `<link>` 在大陆网络可能长时间卡首屏 → 自托管或异步加载。

## 8. 测试

| | 现象 | 根因 | 做法 |
|---|---|---|---|
| ★8.1 | 600+ 个用例只在本地手动跑；推到 main 即部署 | 没有任何 workflow 跑测试 | 开工第一天就加 push/PR 触发的测试 workflow，并放进部署构建命令 |
| 8.2 | 测试随真实数据增长而失败 | 测试读写了仓库里真实的归档文件 | 测试只用临时目录和夹具；被测函数接受文件路径参数，不默认碰模块级缓存 |
| ★8.3 | 测试在某个日期之后开始失败；更隐蔽的：**一周里约 4 天失败** | 夹具里写死日期，或断言依赖"今天是星期几" | 所有日期从测试时钟推导（`NOW − 1 天`）；新增用例后**把时钟依次前移 1–6 天、+60 天各跑一遍** |
| 8.4 | 回归测试把缺陷当成了预期行为 | 先有实现后补测试，照着实现写断言 | 断言写需求，不写现状 |
| 8.5 | 测试沙箱在 `%TEMP%` 累积到 63 份、3.1 GB | 每次运行复制一份仓库且不清理 | 运行结束自动清理，或只留最近 N 份 |
| 8.6 | 测试意外发出网络请求 | 模块被 import 时就启动了后台轮询 | 后台任务只在服务真正启动时开启；测试加离线守卫（[offline_guard.cjs](../test/helpers/offline_guard.cjs)） |

## 9. 金融口径（最容易"看起来对其实错"的部分）

- **Coinbase 溢价**：Coinbase BTC-USD 对 Binance BTCUSDT 的价差，大部分其实是 USDT/USD 汇率（USDT 0.9987 就是 −13 bps）。正确口径是 `Coinbase / (Binance × USDT/USD) − 1`。另：Kraken 数据曾被标成 Coinbase 显示——**换了来源就要换标签**。
- **周末效应**：Coinbase 24h 成交量一周内波动 3.4 倍，而深度只动 1.07 倍，"深度/成交量"评分在周末被系统性抬高。7 日评分应该是"均值之比"而不是"比值之均"，否则一个周日能主导一整周。
- **阈值来自数据本身**：固定的 3.1× 基准让"防线下移"约 82% 的小时都亮着；改为 90 天分位数后中位数约 7.4×。经验常数至少要在界面上标"经验值/假设"。
- **供应商字段的语义要核对**：某接口的 `yearHigh/yearLow` 实际是历史极值；某 `cash` 字段只含储备不含现金。
- **缺数据不能被解读成信号**：90D 基差缺失时，体制判定输出了"基差断崖压缩"。
- **一个结论只用一个口径出场**：同屏两套 mNAV、三个翻转位会让人在关键时刻犹豫。主屏放主口径，敏感性分析收进折叠区。
- **统计检验口径一致**：四项联动检验里三项要求显著性，一项只看"差 10 个百分点"——抽样噪声就能达到。
- **措辞不越界**：去掉"支撑线""建议"类措辞；IV − HV30 不叫方差风险溢价；"预期波动"改称一倍标准差波动。没有回测的方向性结论，明说"未经验证"。

## 10. 前端

- 图表库大版本升级（LightweightCharts v5）API 不兼容 → 锁定库版本，升级时专门验收。
- 布局问题多来自标签嵌套错误和 CSS 媒体查询语法错误 → 改完在桌面 + 手机宽度各看一眼。
- 十几处各自的 `resize` 监听 → 统一一个 ResizeObserver 工具函数。
- 早期一次性堆上大量理论卡片、引用、版本徽标，随后又逐个删除 → 先做最小可用界面，信息密度按需加。

## 11. 协作与流程

- ★**范围漂移**：同一天里 Module 8 被替换了三次（X-Pulse 新闻流 → 对话式宏观 agent → 融资张力指数），最后整模块移除。开新模块前先写一句"它回答什么问题、给谁看"（本项目的选题标准：找被忽略的数据，模拟精品机构的内部分析）。
- **多个 AI 代理并行改同一仓库会冲突**：Devin 的 PR #1 和 main 上的修复重叠，最后只能弃 PR、手工挑增量。同一批文件同一时间只交给一个执行者。
- ★**修复本身也要复核**：11-12 的审计修复在 11-15 复核时发现 6 处问题，其中一个新加的测试门禁每周约 4 天会挡住 CI 和部署。审计/修复报告应写清"验证到了什么、没验证什么"（哪些是读代码得出、哪些实测过）。
- **报告写证据边界**：区分"已复现""读代码确认""未实测"，避免把推断当事实。
- **Windows 环境小坑**：
  - `> nul` 在 Git Bash 下会创建名为 `nul` 的文件（已加入 `.gitignore`），Bash 里用 `/dev/null`。
  - PowerShell 5.1 写文件默认带 BOM，曾让一条提交信息开头多出 BOM 字符（`2ba3d71`）。写给 git 的文本显式用无 BOM 的 UTF-8。
- 旧 worktree 和指向临时目录的 `.claude/launch.json` 配置会残留 → 定期 `git worktree prune`。
